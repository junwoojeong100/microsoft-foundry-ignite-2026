Required lab · Sign in with the initial password and register your own MFA

Sign in with your own UPN and the initial password delivered separately. Accounts for a lab that lasts a few hours do not force a password change, and you complete MFA registration and verification yourself. UPN stands for User Principal Name, that is, a sign-in ID of the form username@domain. Do not confuse it with an email address or a GitHub username.

Open Azure Portal ↗ · Use InPrivate or a separate browser profile on an approved training network and device.

YOUR ACCOUNT AND ROLES

Check your account and permissions, then create resources inside your own RG.

The 9-step screens and video below show a basic Prompt Agent example carried out under these criteria. You can use the same account and permission criteria in other Foundry labs; the model, tools, and resources to create follow each lab's own text.

Handoff boundary: The operator hands off after providing accounts, RGs, RBAC, and subscription preconfiguration. Participants create the resources they need, such as Foundry, projects, models, and observability, themselves in their own RG. Entra account types and Azure RBAC are separate criteria, and being a Guest or a Member does not by itself give you permission to create resources in Azure.

Naming rule example: The UPN and RG you are assigned differ by event (for example, user01@<tenant initial domain> and rg-user01). Use the actual UPN and RG on your own assignment sheet, and do not type the long names from the recording as they are.

Account creation, subscription resource provider (RP) registration, role assignment, and wrap-up are tasks in the Foundry Operator guide. Participants do not receive operator roles or manage other participants' permissions.

Key changes in 2.0, the 6 execution architectures, and the relationship to Foundry

The host decides permissions: mode: "empty" starts without a host shell, file system, or default tools, and it is the required baseline for multi-user or shared services (mode: "coding-agent" is meant for CLI-like coding agents, so do not use it on a shared server). The app decides which tools to provide and the tools.availableTools allow list, and uses github.token or github.tokenProvider to pass and refresh each session's user credentials. These are the names in the 2.0 repository docs; the announcement blog describes the earlier flat names such as gitHubToken and availableTools.

Storage and resume: Session state is kept in external storage and resumed by using a journal together with the client-level sessionFs and a per-session state.createSessionFsProvider. The app is responsible for checking ownership so that it does not open another user's session.

Embedding and connection: Built on a C ABI, it supports TypeScript, Python, Go, .NET, Java, and Rust, and you choose among in-process embedding, child process, and shared service architectures. AHP (Agent Host Protocol), a separate public protocol, lets multiple clients connect to the same running session, and it is not a tool protocol that replaces MCP.

Names explained · The Microsoft Copilot harness and SDK evolved from, or were rebranded from, the GitHub Copilot harness and SDK

Bottom line: The Microsoft Copilot harness evolved and was rebranded from the GitHub Copilot harness, and the Microsoft Copilot SDK (2.0) is the new name of the GitHub Copilot SDK (renamed items at a glance).
